# 定位代码空间与审计覆盖

## 选择可用证据源

立即检查当前工作区、用户指定的代码/文档入口和宿主可用工具，不把审计请求改写为泛泛建议。先遵循项目已有约束；文档用于定位，当前实现与启动引用决定结论。

| 可用形态 | 做法与局限 |
| --- | --- |
| 本地 Luau / Roblox-TS / Rojo 项目 | 枚举源码、项目映射、启动脚本、包清单和锁文件。Rojo 配置名可能自定义；核对 sourcemap/映射，不能只找 default.project.json。追踪生成代码与部署产物是否一致。 |
| Studio 实时源码 | 用可用只读接口列出连接实例，确认目标 Place/Universe、编辑或运行上下文、脚本启用与 RunContext；按实际 DataModel 路径读取，不要求某品牌 MCP。保存 revision/时间，防止前后版本混用。 |
| 已导出 place/model/快照 | 读取宿主支持的格式和源码映射；未解析二进制、模型内脚本、包或动态内容列为缺口，不把空搜索当作无脚本。 |
| 只有片段或文档 | 先分析局部事实并列出需要补齐的入口、调用方及依赖。无完整源码时不输出项目级安全结论。 |

存在多个候选项目时先用用户路径、当前连接和项目身份匹配；确实无法判定目标才询问。源码只在 Studio 时不要重复扫描本地笔记来代替代码审计。不得为读取源码启动游戏、require 未知模块或自动安装执行依赖。

## 读取与快照策略

建立代码地图与覆盖账本不要求复制源码。默认原地读取，按以下顺序缩小上下文：

1. 先取路径、执行位置、启用/注册关系、版本及包清单等索引；搜索只返回文件名、行号和必要上下文。
2. 沿实际入口、危险效果或具体候选，读取函数和所需调用方/下游；需要完整上下文时再读整文件。不要把所有脚本正文拼成一次巨大返回。
3. 复用已读取的同版本证据；新任务只补缺失部分。源码改变、配置不同或需要独立反证时再读取相关位置。

仅在 worker 无法访问证据源、分析工具确实需要本地输入、需要固定一致版本，或用户要求离线导出时创建快照。先明确用途、范围与后续消费者，复制相关脚本及必要依赖；不要为可能用到而预先逐个创建全库 `.lua` 文件。

桥接若支持直接写入本地，可在工具内按需批量导出，仅返回文件索引、原路径、revision/哈希、大小和搜索摘要。全量直存只有在完整离线分析或工具能力限制确实需要时才选用，并说明理由；它不是默认流程。不要把已完整回传到对话的源码再由模型逐文件重写，也不要把源码副本混进生产源码、Rojo 映射或依赖目录。若工具不支持直接落盘，如实采用必要片段和读取接口，不假定复制没有 token 成本。

客户端表现、音效、相机与视觉模块可根据执行位置及调用关系安排较低优先级。涉及服务端复用、RPC 转发、共享状态、动态加载、资源放大或候选链时仍须深入；不能只按文件名判安全或永久排除。第三方危险路径同样必须读实现。未读取的范围保留为待查/未覆盖。

## 两张图和一份账本

先做简短文本关系图，找到候选后再精读；此阶段无需渲染所有文件的依赖大图。

1. **可达图**：启动脚本 → 加载器/框架注册 → 服务端入口 → 校验 → 业务调用 → 危险副作用。包括包装 RPC、自动扫描注册、事件订阅、FeatureFlag 和服务器角色条件。
2. **状态图**：资产/权限/进度/对象状态由谁拥有，谁可写，在哪份 profile/key 或外部系统持久化；状态在哪些阶段可转移、重试或恢复。
3. **覆盖账本**：每个入口/危险效果记录来源与 revision、启动条件、可控字段、调用链、涉及不变量、负责人、状态、证据和缺口。可用一份 Markdown 表维护，无需新数据库。

状态采用 `待查 / 已追踪 / 已验证 / 被防护阻断 / 不适用 / 未覆盖`；每次结论要带来源。发现依赖由另一 agent 检查时把责任和返回条件写清楚，不能视为自动覆盖。

## 双向枚举，防止只盯 Remote

- **从输入端**：原生/封装 RPC、Prompt/Click/Touch/Tool/拖动、玩家控制的物理状态、文本/配置、交易邀请、收据、消息订阅、传送数据、后台管理。
- **从效果端**：资产增减/所有权、奖励标记、保存/迁移/删除、权限变化、共享实例修改/销毁、跨玩家广播、HTTP/动态资源加载、按请求增长的克隆/循环/队列。
- **从生命周期**：初始化与加载中、出生/死亡/重置、取消/超时、PlayerRemoving、会话释放、BindToClose、异步回调、跨服接管。

本地优先用快速文件枚举和内容搜索；Studio 使用可用层级/脚本搜索。根据查到的封装补充关键词，例如框架的 `CreateService`、`Client`、`Listen`、`Handle`、`Invoke` 等，名字本身不证明暴露。实例属性、标签和连接位置也可能决定可达性。

记录搜索边界、排除目录与截断。结果分页/超限就缩小目录、按机制拆分或继续分页，直到重要结果完整。第三方目录可在第一轮独立清点，进入危险路径后必须读其实现，不能永久排除。

## 选读和收敛

优先高价值、跨玩家、持久化、权限与资源放大路径，再覆盖其余实际入口。按风险安排顺序，不以函数数量或匹配数量代替覆盖。

已提供的小型完整项目可逐个读完业务源码及相关依赖，无需先另建快照；大型项目分机制、分批补齐入口与效果链。未读代码留在账本中，不能靠关键词未命中排除。

先读函数及必要调用方/下游，保留少量证据摘录与位置；仅在需要时扩展文件范围。共享组件读一次，记录版本和结论供复用；调用方式/配置不同要重新验证前提。

平台行为或限制会影响结论时查当前 Roblox 官方文档；记录链接和日期。无法联网仍检查安装版源码，明确外部规则尚未核实。不要把记忆中的平台限制作为复现证据。

没有可读代码时，明确还需什么材料并交付已有局部分析；不创造模块、调用关系或扫描成功数字。
