# 按机制选择检查面

先确认真实存在且已启用的机制，只展开相关行。关键词用于定位；结论回到入口、调用者与结果。使用可用的源码搜索、Studio 读取或导出接口，不依赖某种工具。

## 入口、交互和权限

|存在什么机制|优先定位|关键约束与验证|
|---|---|---|
|RemoteEvent / RemoteFunction / 网络包装器|服务端注册、生成代码、路由表、方法白名单、中间件|实际传给处理器的身份；客户端能选的方法/目标/键；包装器何时验证、失败是否继续；从 sink 反查遗漏入口|
|Prompt / ClickDetector / GUI / 拾取|服务端事件到发奖/开门/购买|服务器验证对象、距离、角色状态、资格和重入；界面和客户端等待不作授权；按事件类型核实引擎保证|
|Touched / Tool / 角色动作|触碰、装备、激活、角色/工具事件到结果的链|事件触发者与受益者是否一致；工具/目标的归属与存活；重复触碰、身体多个部件、重生及旧连接是否重复结算|
|Instance / 路径 / 对象编号作为输入|FindFirstChild、索引表、模型选择和目标解析|对象属于允许容器且语义正确；拥有该对象的权限；对象被销毁/替换后是否失效；服务端收到 Instance 不等于此玩家有权操作它|
|管理 / 调试 / 运营 / 配置更新|命令调度、权限、测试开关、外部回调|按动作和目标授权；角色/群组查询失败时行为；发布配置中开发入口是否可达；客户端存在管理 UI 不等于越权|

阅读网络库实际版本的注册、分发、参数处理和调用选项；定义了方法不代表已远程暴露，也不代表自动获得校验。

## 玩法、物理和资源

|存在什么机制|优先定位|关键约束与验证|
|---|---|---|
|客户端影响物理 / network ownership|移动、载具、投射物、碰撞、所有权设置|哪些位置/速度/命中被信任；服务器如何约束；延迟补偿是否允许伪造收益|
|战斗 / 比赛 / 排名|伤害、命中、技能、回合结束、胜负和奖励计算|服务器决定资格、弹药/冷却、敌我、生命状态与结算次数；若结果由服务器独立模拟，不把客户端回放可篡改误报为结果篡改|
|地图移动 / 区域奖励 / 传送|进出区域、检查点、到达判定、传送目的地参数|空间到达是否足以获得价值，是否还需服务端进度/资格；跨场景数据来源与消费位置；传送或返回后旧会话任务是否继续|
|任务 / 在线奖励 / 每日签到 / 活动|进度来源、达成判断、领取、周期重置|进度来自服务器可验证事实；周期、时间和奖励档位由服务器确定；重置与领取顺序、重复事件、离开重进保持一次结算|
|昂贵请求 / 对象创建 / 批量操作|遍历、深层表、任务、物理对象、广播、外部调用|先验证再工作；单次与累计上限；退出后释放；广播/重试/嵌套放大成本；隔离测量，不把无限请求假设当实测|

物理影响或显示差异需要追到服务器信任它并改变伤害、奖励、权限或资源的路径，才能说明服务端影响。

## 资产、存档和跨边界副作用

涉及下表的持久化一致性，继续读 [persistence.md](persistence.md)。

|存在什么机制|优先定位|关键约束与验证|
|---|---|---|
|购买 / 升级 / 合成 / 抽取 / 退款|配置、成本、扣除、产物、失败恢复|数量有限且符合精度/范围；价格、折扣和产物由可信配置计算；乘法范围、余额与锁；失败不能只保留收益或重复退款|
|交易 / 赠送 / 邮件 / 摆摊 / 拍卖|所有权转移、锁、报价版本、两端更新、佣金|归属和可交易资格在提交时有效；改报价使旧确认失效；源/目标、托管和费用一起恢复；自交易、多角色或离线接收是否改变规则|
|装备 / 设置 / 收藏 / 命名 / 排序|所有动态键和值、写入代理、最终保存对象|允许的槽/路径/配置引用；编码、大小、深度、条目预算及默认值；看似低价值字段是否能破坏整个 profile 的保存|
|付费收据 / 礼包 / 可重复回调|收据处理器、发奖回调、去重与确认记录|支付由可信平台流程确认；PurchaseId 等幂等依据与持久化奖励如何关联；重投、离线、发奖失败、提交后回包丢失；不以客户端购买完成事件单独授权资产|
|DataStore / profile 包 / 自定义持久化|加载、代理 setter、迁移、自动/退出保存、会话释放|加载失败是否误当新号；提交的确切对象；过期会话写入；失败及关服恢复；单 key 保证与跨 key/外部副作用分开判断|
|迁移 / 重置 / 默认模板 / 数据修复|版本判断、兼容层、转换和失败分支|旧数据多次加载不重复补偿；部分迁移失败不覆盖有效存档；引用与深拷贝；先校验迁移结果再开放有价值操作|
|MemoryStore / 消息 / 跨服交易 / 排行榜|发送者、订阅者、缓存、租约、重试、过期|业务身份、版本和幂等键；重复/乱序/丢失/过期后恢复；客户端可影响什么；服务器转发不使原始客户端字段可信|
|外部 HTTP / Webhook / 云配置|URL、认证、响应解析、超时和业务使用|地址和凭据来源；响应可信度与 schema；失败时授权行为；有价值操作的远端成功与本地失败如何对账；不为排查调用真实写接口|

## 第三方库：沿危险操作下钻

持久化、权限、远程分发、支付、跨服通信、反序列化或外部请求交给依赖时，读取 [dependencies.md](dependencies.md)。确定安装版本、初始化选项、实际执行分支，沿危险操作追入传递依赖。

区分调用方误用、库内缺陷和业务超出库契约。README、类型签名、网上最新版本或漏洞公告均不能替代当前安装实现与可达调用证据；不必通读无关依赖。

## 共享检查与负例

- 类型正确不等于业务合法；归属正确也不等于当前可售、可装备或可领取。关联多个实体时，要校验实体之间的关系。
- 固定映射、对象范围校验、生命周期 token、提交时复核、持久化幂等记录可作反证；确认实际路径，不依 API 名称下结论。
- UI 隐藏、公开 ModuleScript、客户端本地 setter、缺少单一限流器、使用第三方库或使用某个 DataStore API，均不能单独证明服务端漏洞。
- 配置未启用且入口不可达的功能应标为潜在启用风险；不要与当前线上可利用入口混写。
- 结束依据是入口/sink 覆盖、关键不变量和失败路径核对情况，不是文件数或漏洞数。
