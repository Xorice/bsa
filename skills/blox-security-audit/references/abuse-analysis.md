# 从代码后果推导恶意利用

每条发现都评估攻击者可能获得什么，或能使谁损失什么；影响分析不能止于“报错”“保存失败”“缺少校验”。只组合项目存在或有明确线索的机制；普通故障不能被无证据地写成攻击者可主动触发。

## 分开表达事实与推测

- **直接后果**：当前代码与适用平台语义已能支持的最小后果，注明静态推导或实际观测。
- **潜在恶意利用**：最值得提醒的获利或破坏方式，用“若……则可能……”说明必要条件、因果顺序和受影响资产/对象。链路未齐仍应提醒，但明确为待验证。
- **证据缺口与阻断**：每个决定性环节的代码位置、未知或有效防护；写出最小补证任务。现有防护阻断时说明为何此组合不成立。

检查正常功能能否承接缺陷后果：资产转出后本方回滚是否破坏守恒；重投是否再次发奖；旧会话能否影响替代会话；单个玩家的缓存/实例是否消耗共享资源。只列有因果依据的主要风险，不为每条发现套用复制、免费购买、崩服等标签。

确认代码缺陷与确认潜在利用链是两次判断。前者成立、后者缺证据时，正式发现仍保留，潜在利用写在该发现下面；不额外增加确认漏洞数量。摘要与优先发现表也应提示最重要的条件性风险，不能只藏在附录。严重度可参考有依据的潜在损失，置信度与证据边界单独记录。

## 示例：保存失败为何值得提醒复制风险

以下为通用机理示例，不是任何当前项目的结论：

> **直接后果（源码推导）：** 客户端可控的非法编码键进入包含库存与货币的同一 profile，导致该保存单元被拒绝。
>
> **潜在恶意利用（待验证）：** 若保存失败后仍允许转出资产，且接收方能保存而本方最终恢复转出前的快照，攻击者可能保留接收方资产，同时恢复本方原有物品或余额，造成资产复制或消费回滚。
>
> **还需核实：** 转移是否受保存健康状态约束；双方提交和恢复协议；非法字段是否会被清理后重试保存；会话释放与重登实际加载哪次快照。未追完这些路径，不能声称已经复制成功、离服立即回档或能无限刷取。

这里通常是旧存档恢复造成资产重复，不是直接读取或克隆任意玩家的存档。修复不能只抑制报错：入口约束阻断新增污染；已有污染会话需要恢复可保存性并约束对外转移，不能盲目踢出或恢复旧余额。

[Roblox 官方安全说明](https://create.roblox.com/docs/scripting/security/client-server-boundary#data-store-manipulation)包含非法 UTF-8 键/值及保存失败与交易复制的通用风险；它支持机理，不证明某个项目的完整链已成立。涉及平台具体行为时核对当前官方资料。

## 转换成修复与回归

从潜在利用倒推必须保持的不变量，例如“失败恢复后同一物品只在一方存在”。补证与回归优先选正常对照、非法状态拒绝、单侧提交失败及恢复后断言；记录实际执行结果。机理用业务顺序和证据位置解释即可，不附连接真实目标的利用脚本、自动获利循环或真实账号信息。
