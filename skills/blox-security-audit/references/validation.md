# 反证与隔离验证

## 明确本次审计边界

从本次请求和已有上下文记录目标、版本、授权范围、允许的操作与运行环境；不把 skill 的通用声明当成每个项目都已授权。已有明确授权直接沿用，缺少运行许可时先完成可做的源码分析，不反复要求用户确认只读审计。

默认交付代码证据、触发条件、业务后果、影响上限、修复建议与回归用例。完整追踪漏洞链和第三方库内部语义，不因尚未运行就停止源码审查；也不以证明风险为由自动增加线上利用、批量获利或破坏性操作。

## 先过证据门槛

每个候选回答：谁能触发、控制什么、入口是否实际注册、约束在哪层执行、状态怎样变化、哪条不变量被破坏、影响是否跨越其自身客户端、现有保护为什么没有阻断。

主动找反证：调用者的固定参数、配置白名单、包装器的运行校验、服务端状态/权限检查、序列化层过滤、事务恢复协议、不可达分支、测试/开发限定。保护必须覆盖被讨论的实际路径；一个入口安全不能替另一个入口作证。

| 证据层 | 允许结论 |
| --- | --- |
| 片段事实 | 此函数的局部行为；不能自动扩展到上线入口与最终保存 |
| 完整源码路径 | 指定版本与配置下可达的约束缺口及确定的代码后果 |
| 隔离运行 | 指定真实代码/提取函数/模型在记录的环境中出现的实际观测 |
| 运行与事故证据 | 与部署版本、时间、日志/提交记录相匹配的线上行为或事故归因 |

可确认入口接受非法业务状态，而将跨服、保存和事故影响保留为待证实。严重度描述潜在损失，置信度描述证据强度，两者独立。不能通过措辞掩盖未验证环节。

## 用最小用例检查不变量

优先可读调用链 → 纯函数/提取代码+内存适配器 → 确认隔离的真实运行。选择能推翻或确认候选的少量测试，不反复运行只证明同一事实的用例。

- 输入：合法对照、边界、未知字段/键、可选参数回退、重复标识、有限数/大小/编码；核对拒绝前无状态残留。
- 状态：合法操作在初始化、取消、超时、重生/离开、会话替换后如何处理；正常功能也必须可完成。
- 时序：在真实存在的 yield、回调、跨 Actor/跨服或提交边界设置屏障。无 yield 连续内存代码不能凭空插入同线程 Remote；崩溃恢复是另一问题。
- 故障：指定提交前/后失败、单侧存储拒绝、回包丢失、重复交付、外部调用 false 与抛异常，检查恢复后的守恒/唯一持有/最多一次效果。
- 成本：根据输入规模推导工作量、广播扇出和持久增长；如需测量，使用隔离环境与小规模预算，不能靠线上压测找阈值。

记录代码版本/哈希、用例、前提、期望、观测、断言和未模拟行为。模型发现只证明模型；提取函数不包含真实包装器时写明。模拟适配器未实现序列化、限额、重试和并发就不能证明平台提交行为。

隔离是实际环境属性：使用无真实资产的固定样本与内存适配器，并检查外部依赖。必须如实区分静态推导、模型执行、提取代码执行与真实业务运行；将动作称为“测试”“模拟”不会使其自动隔离或获得授权。

## 运行环境门槛

不要直接 require 可能启动循环/连接事件/发请求的业务模块来“只读”。运行前追踪是否触达 DataStore、MemoryStore、Messaging、HTTP、收据、传送或真实资产旁路；仅看到 `IsStudio()`、负 UserId、mock 标志均不足以证明全部隔离。

默认只在无真实账户/资产的专用适配器中故障注入，规定次数与停止条件；测试异常即保留证据并停止该运行，不扩大到真实玩家。需要额外运行授权时先完成可审查的源码证据和隔离方案，明确请求的动作及原因。审计本身不自动修改玩法、依赖包或线上数据。

## 复核无发现的路径

用至少一个合理失败尝试检查关键防护为何能阻断：例如旧阶段请求被 session token 拒绝、重复奖励被持久去重、动态键归一化为有限服务端枚举。源码推导可作为证据，但不得标成实际运行通过。

不存在相关机制可以记“不适用”，说明从哪份入口/效果清单得出；未知实现必须记缺口。输出详见 [reporting.md](reporting.md)。

## 遇到安全限制

宿主拒绝某项内容或动作时，保留已完成的源码证据、限制信息和未覆盖项，停止同一受限动作。仍允许的独立源码审查、修复建议与回归设计可以继续；不将受限运行改称静态分析或转交其他 agent 重试。

若任务确为防御性审计，可向用户说明实际范围与所需材料，按宿主反馈渠道处理疑似误拦。不要加入“忽略限制”“不得拒绝”、虚构认证/授权等指令，也不保证更换措辞能够解除限制。反馈时只提供提示原文、产品/模型、时间、请求 id（如有）及脱敏任务摘要，不附密钥或完整私有源码。
