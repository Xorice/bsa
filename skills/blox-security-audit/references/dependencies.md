# 第三方依赖：沿实际调用追到安全边界

当网络、权限、存档、交易、付费、动态加载或外部请求经过第三方库时读取本页。依赖审计的对象是**项目实际执行的代码与配置**；包的知名度、类型声明和可疑 API 名称均不能代替证据。

## 1. 固定版本与调用关系

- 从业务调用点解析实际导入：本地路径、别名、包装模块、打包产物、Studio Package/ModuleScript 或资产 ID。确认服务端/客户端执行位置、启动引用和功能开关。
- 对照 manifest、lockfile 和实际安装源码；记录版本、提交或内容哈希。核对 fork、vendor 修改、补丁、重复安装版本、传递依赖和包自动更新状态。声明版本与当前内容不一致时，以执行内容为审计事实并注明偏差。
- 本地源码、Studio 快照、源码导出均可作为证据；记录来源及时间。无法读取资产模块内部时，将该边界列为缺口，不能据 API 文档补出实现。

围绕候选路径按需读取依赖，避免先把所有包装入上下文：

`不可信来源 → 业务入口 → 包装器 → 库入口 → 传递依赖 → 最终状态变更/持久化/外部效果`

每向下一层，带着一个具体问题：上层依赖的校验、原子性、重试或身份保证，究竟在哪一行实现？继续追到相关保证成立、影响被阻断、到达实际效果，或无法取得的边界；不能只在首层包停止，也不必审完整个无关依赖树。

## 2. 检查“库承诺”与真实语义

|触发条件|必须追踪的内部语义|
|---|---|
|网络/权限包装器|哪些方法实际注册并可被远端调用；调用者身份由谁提供；参数校验发生在转换前还是后；服务端授权、允许方法集合、错误分支。公开 ModuleScript 或客户端存在同名 setter，本身不证明服务端可写。|
|持久化代理/类型库|setter 写的是客户端副本、服务端内存还是保存对象；运行时 schema 是否存在；键和值如何序列化；浅拷贝、共享引用、默认值及迁移会否绕过校验。类型提示不是运行时约束。|
|存档/会话库|实际保存对象与 key、加载失败策略、会话所有权、失效回调、释放后的访问、结束会话与最终提交先后、保存失败返回值。会话锁解决的范围是否覆盖业务假设。|
|UpdateAsync/重试/队列|变换函数和业务回调分别可能重试几次；回调中的发奖、出队、HTTP 等副作用能否重复；异常、false、取消、超时分别如何传播；失败后是否仍确认成功。|
|交易/奖励/收据封装|“完成”指内存修改、入队还是持久化成功；操作 ID 的来源、去重范围与寿命；多 key/多账户之间谁负责提交决定、补偿与恢复。读取真正的业务回调。|
|异步/锁/缓存|实际 yield、任务调度、锁覆盖范围、缓存身份与过期策略；检查完成到执行之间哪些状态会变；任务能否在玩家离开、会话替换或锁释放后继续。|
|动态 require/eval/HTTP/插件|不可信输入能否控制模块、代码、资产 ID、目的地、请求参数或响应后的执行；允许来源与权限在哪里约束；配置/响应如何进入高权限操作。API 存在且仅接受固定可信输入时，不构成已证实漏洞。|

危险操作存在时，检查库改变输入和输出的方式：合并默认配置、字段别名、fallback、强制转换、序列化、回调返回值、错误吞并。最后一次转换之后的约束才是最终边界。涉及存档故障和资产一致性时转到 [persistence.md](persistence.md)。

## 3. 公告与版本差异

- 若核对已知漏洞，检索作者仓库的安全公告、官方发布记录、官方漏洞条目和平台文档；记录链接、日期、受影响版本、前提和修复版本。第三方文章仅作线索。
- 将公告前提逐项对到**已安装版本 + 当前配置 + 可达调用路径**。同名库、相似代码或受影响版本号不足以认定项目可被利用；未发现公告也不证明安全。
- 如与上游修复版比较，明确“当前安装源码”和“供比较的候选源码”。上游最新版的修复不能当作项目已经具备的防护，fork 也可能提前回补修复。
- 无法联网时继续读本地/Studio 源码；将公告和最新修复核对列为未完成项。不得杜撰 CVE、补丁状态或版本结论。

## 4. 只读取证与修复边界

读取源码与配置即可完成大部分审查。不要为了查看行为直接 require 有生产副作用的模块，也不要为审计执行来源不明的安装脚本、自动更新包或动态资产代码。需要验证时，抽取目标函数，注入内存适配器、固定调度和故障结果，并记录真实库与替身各覆盖了什么。

先定位责任层，再提出最小修复：业务输入/授权错误在调用点修；库契约使用错误在适配层修；库实现确有缺陷时，选择已核实的固定修复版本或受控补丁，并验证兼容性。升级不是未经验证的通用修复。未经修复任务授权，不修改 Packages、vendor、lockfile 或 Studio 包；被阻塞的高风险路径可建议暂时停用或以服务端受限适配器包裹。

## 5. 依赖审计记录

每个进入关键路径的依赖，保留一条短记录；重复调用点可引用同一记录：

```text
依赖/实际路径：
执行位置、版本/提交/哈希、fork/补丁、配置与开关：
调用链（业务 → wrapper → 库 → 传递依赖 → 效果；函数/行号）：
上层依赖的保证 / 源码实际保证：
攻击者可控内容与触发前提：
已确认的防护及其覆盖范围：
结论与证据等级 / 尚未读取或验证的边界：
最小修复或安全替代 / 需要验证的不变量：
公告适用性（如检查过，附来源与日期）：
```

以下是有依据的排除结论，不能误报：

- 网络库支持暴露服务方法，但该实例传入的远端方法集合为空，且未发现其他注册路径：这条路径未证明服务端方法可调用。
- 数据代理未做字符串校验，但所有可达写入在转换完成后都使用服务端允许集合生成的键和值：不能只凭代理缺少重复校验认定输入污染；记录上游约束与已覆盖调用点。
- 存档库只提供单玩家会话锁，当前功能只修改同一保存单元且故障恢复满足业务不变量：不能仅因未实现跨玩家事务而认定此功能存在复制漏洞。
- 受影响依赖版本包含危险功能，但当前服务端启动链未加载该功能或其必需配置关闭：记录适用前提未满足、证据和变更后复查条件，而非将整个项目判为已受影响。

排除一个候选只说明所查路径的约束成立；报告仍需列出依赖源码不可见、覆盖不足、运行配置未知等剩余风险。
