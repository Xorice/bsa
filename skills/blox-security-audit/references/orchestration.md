# 子 agent 分工与上下文控制

有可并行的独立问题且宿主支持 subagent 时使用；并发数由实际能力决定。不依赖某工具名，不自动创建新的用户会话。无委派能力时，在同一账本里串行完成相同分工，并说明未进行独立复核。

## 按边界分工

先由主 agent 建立项目与入口地图，再派出适量专查。按实际机制选角色，而不是固定人数：

| 任务 | 边界与交付 |
| --- | --- |
| 交互与权限 | RPC/世界交互/战斗/管理入口到实际变更，检查身份、状态、范围、资源成本 |
| 持久化与经济 | 所有可写 profile 字段、资产转移、奖励、收据、恢复和迁移的不变量 |
| 依赖实现 | 多个业务共用的网络/存档/授权库，返回特定版本、配置与被保证/未被保证的语义 |
| 独立反证 | 读取高风险候选完整链，寻找下游防护、不可达条件、错误假设与最小验证 |

共享库尽量明确一个实现审查负责人，其他 worker 请求需要的语义；业务 worker 仍负责验证自己调用时是否满足库前提。不可把跨域链切断：例如装备写入影响交易保存，主 agent 要把两边结果合并检查。

## 下发最小任务包

只传项目身份、相关文件或 DataModel 路径、版本、范围、待回答问题、证据要求和必要专项链接。先确认 worker 能否直接使用相同的读取/搜索能力；能直接读就传位置与短摘要，不预先导出全库。要求 worker 先读主入口，再只读自己的专项；不要让每个 worker 重扫全项目或复制整段聊天。

可用任务格式：

```text
审计范围：<入口/模块/依赖及版本；相关生命周期/失败边界>
目标：<不变量与待回答问题，不预设有漏洞>
证据源：<路径、revision、已建立的账本条目>
选读：<本 skill 下相关 references>
限制：继承本次项目与授权范围；默认只读源码，不启动/调用真实业务；确需运行时由主 agent 按 validation.md 明确隔离与动作范围；不修改其他任务文件。
返回：逐边界覆盖状态、校验两侧的实际副作用、候选及证据、被反证原因、未知与跨域交接、测试实际观测。
```

若 worker 无 Studio/源文件权限，先提供其任务所需的最小只读片段，必要时按 [discovery.md](discovery.md) 创建有限范围快照并标记来源；也可由主 agent 接管该链。不能把缺少 worker 访问能力自动升级为导出整个项目。输出受截断时获取关键证据；“worker 无发现”不等于其范围已验证安全。

## 主 agent 的合并责任

1. 按根因及共同不变量去重，多个入口共用同一修复通常合并；不同故障窗口可保留关联发现。
2. 对高影响发现及排除高影响候选的关键防护亲读关键行/原始结果，校验可达性、配置、实际输入能力、成功/失败分支与副作用，不能只引用 worker 的结论。
3. 将各域的“未知”配对：一域的可控写入，可能是另一域存储/权限/对象选择的前提。建立组合假设后补读跨域链。
4. 独立复核者先从原始材料判断，再看候选描述作反证；不给预期答案，避免重复确认偏差。
5. 回到账本核查未分配、未返回、范围重叠和遗漏；因工具故障或访问缺失而失败的 worker，可在已有权限内转派或接管，不把失败视为无问题。因宿主安全限制而停止的动作，按 [validation.md](validation.md) 保留限制和缺口，不换 agent 重试同一受限动作。
6. 按 [validation.md](validation.md) 的同一门槛归类所有候选；不同 worker 对同类机制结论不同时，比较入口、版本、失败边界及缺失证据。高风险“被阻断”结论若未追到拒绝后的最终副作用，退回补读或明确未覆盖。

## 控制上下文与结题

worker 用证据位置与短摘录返回，不回传全部文件或重新落盘同一份源码；共享摘要必须保留版本、前提和未知。主 agent 复核关键原始证据及跨域连接，无需再读每个 worker 的全部材料。用账本断点续查，避免重新扫描相同版本。代码变化后仅失效受影响的结论与调用链。

结题前逐项确认高价值入口的相关生命周期与失败边界均有证据或明确缺口、候选均按统一门槛归类、可用历史发现均有当前去向。未完成部分保留为未覆盖/审计不完整，不因模块曾被分配就标已追踪，也不以“已经跑完几个 agent”或预设漏洞数量收尾。
