# 漏洞解释图与离线构建工具

发现漏洞后读取本文件。每个独立问题生成一张图；多个问题依赖同一失败状态时，可合为一张组合利用图。图服务于报告，不能代替源码证据。

## 首屏先说后果和利用程度

每张新图先填写 `summary`，让使用者不用读完技术节点就知道危险。每项用一两句短话，详细论证放报告。使用业务语言和明确数量，如“只扣 1 件材料，获得本应消耗 3 件的完整产物”。

|摘要项|应回答什么|
|---|---|
|直接后果 `direct_effect`|谁损失什么、攻击者获得什么，预期与实际的差额；不要只写漏洞名称或“存在风险”|
|可利用程度 `exploit_extent`|单次效果、能否重复、次数/速率/资源上限与停止条件；自身/他人、单服/跨服、当前会话/持久化的范围|
|成立条件 `prerequisites`|所需权限、资产、功能配置、会话与时序条件；不要把普通玩家漏洞写得像需要管理权限|
|证据边界 `evidence`|哪些是源码确定、隔离观测或真实平台验证；哪些影响链仍未知，数字基于什么初始条件|

有限库存造成的有限次产出不能写成“无限刷”；没有读到转移/持久化路径就不能宣称永久复制或跨玩家获利。未知上限写明未知和缺少的证据，不自行生成数字。结论提醒与报告使用相同证据等级，不能因红色警示卡而夸大。

建议页面顺序：**直白标题与严重度 → 四项影响摘要 → 紧凑主流程 → 分支/关联 → 可展开证据**。技术原因放到图中展开；文件行号不挤进节点正文。

## 图应解释什么

按因果顺序呈现：**触发前提 → 正常交互 / 攻击者可控输入 → 缺失的服务端约束 → 状态改变 / 保存边界 → 潜在危险**。分支展示现有校验在哪些输入上有效，以及遗漏输入如何经过。用回边解释重试、重连或重复结算；跨系统问题明确各自的保存单元。

- 实线 `verified`：已读到的可达源码路径或隔离观测；节点证据写明二者是哪一种。不能据此声称云端复现或事故归因。
- 虚线 `hypothesis`：未实测的影响、尚缺运行条件或依赖行为；标签直接说明欠缺的条件。默认状态就是该值。
- 点线 `blocked`：已确认被现有防护阻断的候选路径；写明阻断位置。它不是一条成功利用路径。
- `fix` 节点表示建议修复。修复未落地时，连接仍为 `hypothesis`，不能画成现存阻断。

只有未发现漏洞时，输出报告中的覆盖、候选反证和剩余限制即可；必要时画已被阻断的候选路径，避免将假想漏洞包装成发现。

## 使用工具

`scripts/render_flow.py` 仅使用 Python 3 标准库，不访问网络，不需要 Mermaid、Node 或第三方库。输入由审计者撰写的 JSON，输出含内联 SVG 的自包含 HTML，可选独立 SVG 与 Mermaid 源码。HTML 无 JavaScript、CDN 或远程字体。主流程采用紧凑多列蛇形卡片，分支与回路通过边编号及完整关联表保留，减少全页长线和文字交叉。

版面采用日常审计文档字号：HTML 正文 14px、主标题 22px、分区标题与直接后果 18px，证据表 13px；SVG 节点正文 16px、直接后果 20px、完整证据 13px。绘图区最大宽度为 1200px，避免宽屏把字体整体放大；窄屏保留横向滚动，打印时按页面宽度缩放。标题、摘要、节点与索引使用较紧凑的间距；仍保留四项摘要、所有关系与证据状态。

用 `main_path` 明确主因果链，其余节点分区展示。推荐主链 4–8 步，将同一校验/消耗阶段的细节合并；超过两三行的解释移入证据。把既有阻断与建议修复放在关联区，不画成成功利用必经步骤。HTML 中完整路径条件与证据可折叠，默认展开旁支关联；独立 SVG 附摘要、全部关系和证据区。Mermaid 源码以注释保存摘要，引用时也应在图前展示四项文字，不能期待注释被渲染成提醒。

将 `<skill-dir>` 替换为本 skill 实际所在目录，输出放进用户项目约定的审计产物目录：

```sh
python "<skill-dir>/scripts/render_flow.py" --input "audit/flows.json" --output "audit/flows.html" --svg-dir "audit/svg" --mermaid-dir "audit/mermaid"
```

按环境改用 `python3` 或 Windows 的 `py -3`。没有 Python 时，先在报告写出四项摘要，再放置 `mermaid` fenced 代码块，并保留相同的证据约定；不要为画图阻塞审计。命令会覆盖指定输出文件，应选择本次审计的输出位置，不要指定输入 JSON 或已有源码路径。

## 输入契约

顶层 `flows` 必填，`title` 可选。每个 flow 的 `id`、`title`、`nodes`、`edges` 必填，支持 `summary`、`main_path`。各层拒绝未知字段和重复 JSON 字段。为兼容旧数据，工具允许没有摘要；此时明确提示未提供，不能据节点自动编造影响。使用本 skill 新生成的图必须提供四项摘要。

|字段|要求|
|---|---|
|`flow.id` / `node.id`|ASCII 字母开头，只含字母、数字、`_`、`-`，最多 64 字符；flow id 全局唯一，node id 在图内唯一|
|`flow.title` / 顶层 `title`|非空字符串，最多 160 字符|
|`flow.summary`|对象，包含非空 `direct_effect`、`exploit_extent`、`prerequisites`、`evidence`；各最多 400 字符、8 行；可选 `severity` 为 `P0` / `P1` / `P2` / `P3` / `未定级`|
|`flow.main_path`|可选非空 node id 数组；id 已定义且互不重复，相邻项存在同方向的边；仅声明展示主链，不改变边的证据状态|
|`node.label`|非空字符串，最多 280 字符；JSON `\n` 可分行|
|`node.kind`|可选，默认 `state`；`actor` / `check` / `state` / `failure` / `impact` / `fix`|
|`node.evidence`|可选字符串，最多 400 字符；短引用如 `server/Trade.lua:81–109, hash abc; 源码确认` 或报告 finding id；不是可执行链接|
|`edge.from` / `edge.to`|图内已定义 node id；允许分支、重复边和自环|
|`edge.label`|可选字符串，最多 120 字符；写条件或欠缺证据|
|`edge.status`|可选，默认 `hypothesis`；`verified` / `hypothesis` / `blocked`|

单文件最多 2 MB、24 张图、合计 400 节点 / 800 边；每图 1–80 节点 / 0–160 边。显式换行限制：标题与边标签最多 4 行、节点标签 8 行、证据 12 行；长文本还会自动折行。复杂独立链按业务或保存边界拆图。无效端点、重复 id、空图、不连通的主链、非标准 JSON 数值、无效 Unicode 和 XML 控制字符会报错并返回状态码 `2`。文件名由受限 flow id 生成；所有文本转义，证据不会被当作 HTML 或脚本执行。工具只做结构校验，**不会自动判断证据真假或推断漏洞**。

格式示例见 [examples/flows.json](../examples/flows.json)。合成数据，仅演示格式，不是当前项目结论。

有多张图时，把更多对象加入 `flows`。HTML 提供分区与索引，每张独立 SVG 可嵌入报告；`.mmd` 是供下游渲染器使用的文本，不依赖在线服务。工具不会生成请求载荷或执行攻击；解释链应聚焦修复和风险，避免放入真实账号、密钥或线上利用脚本。
