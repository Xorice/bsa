# 文本发现与修复结果

直接回复文本或 Markdown，用户要求保存时才写文本文件；不生成图、HTML、Mermaid、SVG、图数据或截图，不运行渲染器。先概括目标、版本、主要损失与整体是否完整，再按独立根因交付，避免大段复制源码。

## 潜在恶意利用不能省略

每条发现先说确定后果，再说明有因果依据的获利或破坏机理、必要条件及待核实环节。不要止于“保存失败”“缺校验”，也不把普通服务故障无证据地写成可由玩家主动触发。

例如非法键使整个 profile 无法保存：**若仍可转出资产，接收方成功保存，而本方最终加载转出前快照，就可能同时保留接收方所得与本方原资产，形成复制或消费回滚。** 未追完转移、保存健康检查、清理重试和会话恢复时标待验证；不能声称已复制、即时回档、无限收益或可克隆任意他人存档。

合理的高影响推测与已确认缺陷并列提醒，不藏在末尾，也不额外增加确认数量。防护已阻断时给证据；没有合理利用链时如实限制影响，不给每项套“复制/崩服”。解释机理与补证即可，不附线上利用脚本、获利循环或真实账号信息。

需要深入专项时按 [companion.md](companion.md) 复用完整版 `abuse-analysis.md`；平台具体行为核对当前官方资料，例如 [Roblox 存档输入与交易风险](https://create.roblox.com/docs/scripting/security/client-server-boundary#data-store-manipulation)。通用机理不证明当前项目的完整利用链。

## 便于另一个 agent 接手

字段可合并行，保留原 ID 与证据/验证状态；无 ID 时分配，合并/拆分说明映射。

```text
ID / 标题 / 优先级 / 缺陷分类 / 置信度
处理状态：待修复 / 已修改待验证 / 已修复且通过所述验证 / 无需修改 / 未完成
位置与版本：路径、函数、行号、revision/哈希；旧报告对应项
不变量与根因：预期、缺口、入口至最终效果、已核对防护
前提与直接后果：角色、可控内容、适用配置/状态、确定损失及证据层级
潜在恶意利用：获利/破坏机理、必要条件、证据等级与缺口
最小修复或实际改动：目标边界、位置、需保留的合法行为
验证：合法对照、触发/失败用例、断言、实际方法及结果；未执行明确写明
剩余问题：补证、迁移/恢复需求与下一步
```

结尾保留已查范围、防护反证和未覆盖项。承接完整版报告时修复前后版本可追溯；默认不覆盖原报告或更新旧图，用户要求同步时保留原审计证据并追加当前状态。不能只输出这份文本来代替用户已要求的修复实施。
