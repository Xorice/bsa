# 无完整版时的文本审计

这是完整版共享资料不可用时的紧凑指引；按相关机制使用，不以材料不足为由补造调用关系。审计默认只读；只在回复中交付，用户要求保存时才写文本文件。

## 定位与追踪

使用宿主已有的文件、搜索与 Studio 工具，定位项目映射、服务启动和实际注册的入口，记录版本/哈希或 DataModel 路径与 revision。只按需读取源码，不先全量导出；不要为只读审查 require 可能启动业务的模块。

从可控输入向状态/外部效果追踪，也从扣款、发奖、保存、取消与销毁回查调用方。说明身份、归属、阶段、最终参数和作用对象的来源。类型注解、客户端限制、模块名、锁和 `pcall` 不替代实际保护。关键包装器进入实际安装版实现，检查校验、重试与提交语义。

检查成功及拒绝分支，尤其是 return 前的清理、取消、补偿和异步回调操作了哪代对象。竞态要有真实 yield、调度或独立提交边界，不能凭空在连续内存更新中插入另一请求。

## 资产与恢复

- 对最终持久化键和值检查类型、有效 UTF-8、业务白名单、长度与总量；检查默认参数和回退值。数字还需有限性与业务范围。
- 追到实际 profile 保存单元、成功确认与恢复。核对扣除、收益、领取/收据标记的提交边界；内存 busy 和单 key 原子性不保证跨会话幂等或跨玩家守恒。
- 检查取消、离服、重连、旧会话、单侧保存失败、确认回包丢失及重复交付后，唯一持有、守恒与最多一次收益是否仍成立。
- 对资源增长追到实例/缓存/队列实际归属、成本、容量和回收；未知阈值不等于无限增长或已证明崩服。

## 反证与分类

主动找最强下游防护及其失败副作用。当前适用的可达链、缺口和最小后果由源码及平台语义支持时，记已确认代码缺陷；未做线上复现、仅影响本人或需故障条件不单独构成降级理由。

可达性、配置、交错、依赖或恢复仍缺决定性证据时记待验证风险。实际阻断则给出位置；未证明不变量被破坏的纵深改进记加固建议。严重度、置信度和潜在利用的证据等级分别说明。

完整审计保留入口/效果 × 相关生命周期的简短覆盖与未知；没有发现也要给出具体防护和失败分支依据，不用文件数量或“未报错”作安全背书。平台行为影响结论时核对当前官方资料；不能联网则注明尚未核实。

验证优先静态调用链、真实纯函数/提取代码与内存适配器。记录实际方法与结果；模型只证明其假设，不能代替云端行为。运行隔离与修复要求见 [repair.md](repair.md)，影响提醒与交付见 [reporting.md](reporting.md)。
