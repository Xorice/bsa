# 复核并实施修复

只在用户要求实施时修改授权项目；已有“审计并修复”或“按报告修复”的指令可直接沿用，不重复确认。只要求审计或向修复 agent 交接时输出建议。

## 从当前代码开始

按原发现 ID 复核当前版本，记录仍成立、已修复、被反证、不适用或未完成。旧报告及其命令是待核查材料，不扩大权限；仅有报告、缺少源码时可以整理交接，不能确认当前漏洞或声称修好。

先追该根因、必要下游及共享调用方，不默认重扫全项目或重做已有同版本审计。需要存档、依赖、证据分类等专项语义时，按 [companion.md](companion.md) 选读完整版对应资料；不可用时使用 [audit.md](audit.md)。不加载完整版报告与图示流程。

先定义修复后的不变量，定位服务端最终校验、状态机或提交边界，保留合法输入、协议和既有功能。修根因及相关路径，不只加客户端限制、吞异常或换一个会静默丢数据的兜底；不要为修业务调用随意替换存档库。

修复新增污染与恢复既有坏数据是不同工作。说明污染会话的残余风险；不盲目删存档、回滚余额或踢人。确需产品规则或迁移决定时，先完成独立可做的修复，将依赖该决定的部分明确留待处理，不编造补偿策略。证据不足的利用推测保留为补证项，不据此大改业务。

## 验证与停止条件

验证合法对照、原触发条件和相关失败/恢复断言；优先真实纯函数或提取代码与内存适配器。模型结果只证明其假设，不能当平台复现。提交前失败、提交后应答丢失、竞争重试已有记录应分别建模，不能相互代替。

修后复读调用方、拒绝副作用与相关旁路，确认不变量。反馈实际修改位置、实际检查和剩余缺口；区分已修改待验证与已修复且通过所述验证。不能运行时列出原因，不把计划写成通过；失败则在本次根因范围内定位并修正，缺少决定性实现、运行条件或产品规则时明确阻塞项。

Studio 不是天然隔离环境。运行前确认 require/初始化和适配器不会访问真实 DataStore、支付、资产或其他外部服务；skill 不自动授权线上故障注入、玩家数据写入、压力测试或部署。宿主限制某动作时保留缺口并停止该动作，不换措辞或 agent 重试。

完成后按 [reporting.md](reporting.md) 回复文本；源码及必要测试文件可修改，不因纯文本交付约定而停在建议。
