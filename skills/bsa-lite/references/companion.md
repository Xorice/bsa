# 与完整版协作及共享审计指引

`bsa-lite` 是 `blox-security-audit` 的文本与修复入口。两者共享证据标准；完整版负责审计文档与图，lite 聚焦文本发现、当前代码复核和已要求的修复。

## 按需定位共享资料

从宿主的技能清单或已选中的安装路径定位 `blox-security-audit`，不要假定全局目录、平台或 MCP。无需先加载其 `SKILL.md`；只打开对应 `references/` 文件，已读过且版本相同的内容直接复用：

| 当前问题 | 完整版目录内的文件 |
| --- | --- |
| 新审计的入口、版本、覆盖与证据读取 | `references/discovery.md` |
| 候选、业务不变量、失败分支、异步代际 | `references/reasoning.md`；具体交互机制按需加 `references/surfaces.md` |
| 存档、跨玩家资产、收据、奖励、故障恢复 | `references/persistence.md` |
| 危险效果经过依赖包装器 | `references/dependencies.md` |
| 代码缺陷分类、反证、运行隔离与证据等级 | `references/validation.md` |
| 潜在获利、破坏或扩散机理 | `references/abuse-analysis.md` |

先选当前阶段需要的文件，后续确有问题再补读；不要因为伙伴 skill 可用就把全部资料读进上下文。lite 不加载完整版的报告排版、图示、渲染器或分工流程。共享规则里的报告/图输出建议不改变 lite 的纯文本交付；用户授权决定是否修改业务。

完整版或所需资料不可用时，用本 skill 的 [audit.md](audit.md) 检查相关机制，明确未完成的专项；不要为此自动安装 skill 或阻塞已能推进的修复。共享资料缺少某段实际实现时，仍是代码证据缺口，不能用规则补成事实。

## 发现与修复的交接

- 接收完整报告时，按发现 ID 取得目标与版本、源码位置、不变量、缺陷分类、潜在利用前提、最小修复与回归断言；缺失项按当前代码补齐。复用相关证据，不先重扫全项目，也不默认旧结论仍成立。
- 用户只要求审计时交接建议；已要求“审计并修复”时沿用该授权继续。加载另一 skill 本身不启动 subagent，也不扩大线上动作权限。
- 返回原 ID、修复前后位置/版本、实际改动、验证结果与残余风险；合并或拆分说明映射。只有修改而未验证时标“已修改待验证”。
- lite 默认回复文本。用户要求更新原报告时追加带版本的复查/修复记录，保留原审计证据；图与源码版本未同步时明确陈旧，由完整版在需要时更新。不因 lite 的结果自动覆盖旧报告或重绘图。
